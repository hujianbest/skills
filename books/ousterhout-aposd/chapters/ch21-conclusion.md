# Chapter 21: 结论 (Conclusion)

## Core Idea
全书只讲一件事: **复杂性是软件设计最重要的挑战**。所有原则可归为三类——认识复杂性（根因: 依赖与模糊）、识别红旗、以及生产简单系统的思想（深类、适度通用、定义错误不存在、接口/实现文档分离），底层则是对投资心态的要求。

## 全书脉络回顾
- 复杂性的本质 (ch2) → 战略心态 (ch3) → 深模块与信息隐藏 (ch4-5) → 通用性 (ch6) → 分层与抽象 (ch7) → 复杂性下拉 (ch8) → 分合决策 (ch9) → 消灭错误与特例 (ch10) → 设计两次 (ch11) → 注释三连 (ch12-15: 为何写/写什么/何时写) → 演化期守护 (ch16-18) → 趋势检验 (ch19) → 性能 (ch20)

## Key Concepts
- **这些原则的共同代价**: 项目前期额外工作；不习惯设计思维时学习曲线更陡——若唯一目标是"尽快跑起来"，这些思想像拦路的杂活
- **设计是有趣的**: 若好设计是你的目标，设计是迷人的谜题（"如何用最简单的结构解决此问题？"）；干净、简单、显而易见的设计是美的
- **投资回本很快**: 精心定义的模块被反复复用；半年前的清晰文档在你回来加功能时省时间；技能本身复利——熟练后好设计并不比脏设计慢
- **终极奖励**: 好设计师把大部分时间花在有趣的设计阶段；差设计师把时间花在复杂脆弱代码里追 bug

## Key Takeaways
1. 把全书当工具箱: 遇到设计决策时逐条对照（深吗？藏住信息了吗？错误定义掉了吗？...）
2. 提高设计技能本身是最划算的长期投资
