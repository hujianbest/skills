# Chapter 10: 定义不存在的错误 (Define Errors Out Of Existence)

## Core Idea
异常处理是软件系统最糟糕的复杂性来源之一。降低其破坏的最佳方式不是写更多 handler，而是**减少必须处理异常的位置**——最高招是重新定义语义让错误条件根本不存在。

## Frameworks Introduced
- **异常为何昂贵**: 特殊情况代码天生比正常代码难写；异常处理会催生新异常（重发包→对端收到重复包；冗余副本也丢了）；语言支持冗长笨拙（try-catch 样板超过正常代码）；难以测试——"**没被执行过的代码是不能工作的代码**"（研究: 分布式系统 >90% 灾难性故障源于错误处理不当）
- **异常过多是自找的**: "检测到的错误越多越好"导致过度防御风格；抛异常很容易、处理异常很难；类抛出的异常是其接口的一部分——异常越多接口越复杂、类越浅（异常可穿透多层栈，影响的远不止直接调用者）
- **四种减少异常处理的技术**:
  1. **定义不存在 (define errors out of existence)**: 修改 API 语义使正常行为覆盖所有情况
  2. **异常屏蔽 (exception masking)**: 低层检测并处理掉，高层无感知 → 类更深（接口-异常、功能+屏蔽代码）。适用: 分布式系统常见——TCP 重发丢包；NFS 服务器无响应时客户端无限重试、应用挂起——看似糟糕实则最优（应用对丢文件无能为力；重试集中一处；服务器恢复后应用无缝续跑）
  3. **异常聚集 (exception aggregation)**: 用一个 handler 处理许多异常，置于能捕获最多异常的位置。Web 服务器: 各服务方法不各自 catch 缺参异常，而是统一冒泡到顶层 dispatcher 一处处理、生成错误响应（错误消息在抛出点生成并存入异常）。通用模式: **请求处理系统定义"中止当前请求"异常，在请求循环顶部单点捕获**；RAMCloud 把对象损坏"升级"为整服务器崩溃——复用唯一必要的崩溃恢复机制，还让恢复代码更常被执行、bug 更早暴露（代价: 恢复昂贵，只适合罕见错误）。与屏蔽相反: 聚集最好在高层、屏蔽最好在低层；共同点: 把 handler 放在能捕获最多异常处
  4. **直接崩溃 (just crash)**: 对难以处理且罕见的错误，打印诊断信息后中止。例: malloc 失败返回 NULL 要求每个调用点检查（现实: 没人检查→空指针崩溃掩盖真问题）→ 用 ckalloc 包装: 调 malloc、检查、失败即中止。适用: 内存耗尽（应用也无能为力，还可能 handler 自己也要分配内存）、磁盘硬错误、内部数据不一致。**例外**: 复制型存储系统对 I/O 错误不能崩，用副本恢复——恢复机制贵但那是系统价值所在
- **把特殊情况定义不存在 (design special cases out of existence)**: 同理推广——消除 if 满天飞。例: 选区"不存在"→ 内部恒用空选区（起止同位）表示，复制/删除逻辑无需任何特判

## Worked Example
三个经典 API 对比:
- **Tcl unset**（作者自认 Tcl 设计最大错误之一）: 删除不存在的变量→抛错。但 unset 最常见用途是清理"不确定创建了哪些"的临时状态→开发者全用 catch 包裹。重定义即愈: "删除变量" → "**确保变量不再存在**"——变量本来就不存在时任务已完成，自然返回，无错误可言
- **Windows 文件删除**: 文件被进程打开→删除失败→用户杀进程甚至重启。**Unix**: 标记删除立即返回成功；目录项即刻消失（可建同名新文件），已打开的进程继续正常读写，全部关闭后数据才释放——一次定义消掉了两类错误（删除方的错误 + 使用方的错误）
- **Java substring**: 索引越界抛 IndexOutOfBoundsException→想取重叠区间的调用者要手写夹取逻辑（一行变 5-10 行）。重定义: "返回 index ∈ [begin, end) 的字符（如有）"——负索引、begin>end 全都有良定义行为。Python 切片即此风格。反驳"抛错能抓 bug": 抓住一些 bug 的代价是全系统更复杂→引入别的 bug；**减少 bug 的最好办法是让软件更简单**

## Key Takeaways
1. 抛异常前先问: 这个语义能不能重定义，让这个情况不是错误？
2. 屏蔽（低层消化）与聚集（高层单点）方向相反、目标相同：把 handler 放在覆盖面最大的位置
3. 类的异常清单 = 接口复杂度的一部分，跟方法数一样要节俭
4. 不重要的事情能藏多少藏多少；重要的事情必须暴露（网络通信模块吞掉全部网络错误=灾难）
