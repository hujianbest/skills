# 《一点写代码的心得》系列经典范式深度解构

《一点写代码的心得》系列博文之所以引起众多工程师与管理者的强烈共鸣，是因为它融合了**“大厂三十万行重构老兵的厚重底蕴”**与**“独立开发者亲手折腾 AI Coding 的真诚探索”**。

它既不是高高在上的技术说教，也不是冷冰冰的配置手册，而是一个真实的工程师，在时代浪潮拍打下，用朴素常识进行的反思与突围。

---

## 核心典范一：《一点写代码的心得（五）：AI Coding时代的软件工程》

第五篇是系列在 AI 时代的最高代表作。它的结构、语言与推演逻辑堪称典范：

### 1. 引言与背景（真诚的痛点切入）
- **前情承接**：以引用块连接上篇 TDD 的讨论。
- **坦陈焦虑与自嘲**：
  > “去年这个时候，AI 还在老老实实补全代码……今年倒好，直接上手生成整个项目了。作为曾经的老牌软件工程师，感觉自己的价值突然一夜之间蒸发了。”
  > “打不过就加入，白天公司干完活，晚上回去继续 AI Coding。开了 Cursor 的会员，买了智谱的 API……”
- **端出真实项目现场**：自己的摄影分享网站（ins-app），遇到功能没反应、页面错位、未知异常，反复当“人肉测试”，“好不痛快”。
- **金句下结论**：“表面上看起来是快了，但后期修 Bug、擦屁股的时间，把前期省下的时间全吃回去了。”

### 2. 章节递进与本质剖析
- **`## 1. 买了Tokens，然后呢？`**：
  - `### 1.1 一个摄影网站的难产`：经典的 CRUD，“能跑”和“能用”之间隔着巨大鸿沟。
  - `### 1.2 我好像懂了一点`：AI 只能看局部文件，看不见全局契约。引出**热力学熵增**——“以前一个月才能堆出来的屎山，现在几天就堆好了。这算不算 AI 的功劳？（苦笑）”。
  - `### 1.3 那是 AI 不行吗？`：承认 AI 局部编码秒杀初中级工程师。“没有约束的创造力就是混乱。”
- **`## 2. Harness Engineering 是什么？为什么突然火了？`**：
  - 用摄影做生动的三代类比：Prompt（对摄影师提一句话需求）-> Context（递给摄影师一本参考手册）-> Harness（设计一整间摄影工作室的工作流与质检标准）。
  - 引用权威共识：`"Agents aren't hard; the Harness is hard."`
  - 数据佐证反直觉事实：Anthropic 9美元残次品 vs 200美元完整品；同一模型环境不同，成功率从 42% 飙升至 78%。
- **`## 3. 绕了一大圈，回到原点`**：
  - 尝试 TDD：代码对了，但方向跑偏了，“当然，Tokens 消耗明显多了……”
  - 尝试 SDD（Speckit、OpenSpec）：先写蓝图再盖楼，方向对了。
  - 顿悟与溯源：**“它们不就是咱们那些经典的‘老旧’软件工程方法，在 AI 身上的固化吗？”** 在华为摸爬滚打五年的分治、抽象、接口契约，原来全是最宝贵的基本功。
  - 公式升华：`软件工程 = 编程 + 时间` -> `AI 软件工程 = AI 编程 + 软件工程方法`。
- **`## 4. 为什么要造自己的轮子？`**：
  - “穿别人的鞋，总不太合脚”；
  - 真正的核心竞争力是审美品味与判断力（再次类比摄影：人人有手机，为什么专业摄影师拍的大片不一样？因为抽象、设计与 Trade-off）。
  - “你的 Harness，就是你看待这个代码世界的方式。”
- **`## 5. Harness Flow：把老方法装进新瓶`**：
  - 交代定义阶段（SDD）、执行阶段（TDD + Fagan 审查法）、闭环阶段（DoD 验证）；
  - 分享实操最大教训：不要教 AI 怎么敲键盘，教它**“纪律”与“红线”**；核心主文件留规则，参考资料全下沉到 references；
  - 坦诚贴出真实项目：`ins-app`、`garage-agent`。
- **`## 6. 总结`**：
  - 回归初心：“做好每一件小事，把基本功练扎实。”
  - “AI 从来不是来取代你的，它是来放大你的。但前提是，你的脑子里得有值得被‘放大的东西’。”

## 核心典范二：《一点写代码的心得（三）：“你可别再重构了！”》

第三篇展示了如何将传统大厂超大型架构重构写得既惊心动魄又妙趣横生：

### 1. 引言切入
- 老同事散步时的一句“警告”：“你可不能像以前一样搞那么多重构了，要是引入问题了，就是生命安全的大事。”
- 反思早年的心高气傲，引出对重构的敬畏。

### 2. 实战血泪与数字考古
- 经历两个大型产品合并、翻新近 30 万行代码：高光时获技术认可，至暗时现网事故导致“那一年的绩效凉凉”。
- 提出“数字考古”与“切斯特顿栅栏”：你不知道路中间的木桩当初为什么立在那，千万别轻易拆掉。

### 3. 工程破局与心法
- 绞杀者模式（老城改造，在旁边建新城让商户自然迁徙）；
- 区分改行为与改结构（两顶帽子）；
- 结尾升华：代码不是巴比伦塔，而是盆景，需要克制与敬畏。

## 避坑镜鉴：《第六篇：Agent的最小Harness怎么搭》为何曾陷入平淡？

| 问题定位 | 为什么会写垮？ | 正确的改造姿势 |
| :--- | :--- | :--- |
| **丢了第一人称痛点** | 开篇直接罗列 OpenAI 和 Anthropic 论文，像在写行业调研报告。 | 承接第 5 篇摄影网站的实战后续，聊在真实业务中 Agent 依然失忆、依然口头完成的抓狂瞬间。 |
| **陷入清单说明书** | 机械式罗列 4 个文件配置模版、5 个避坑要点，读者读完像在看 API 手册。 | 把文件提炼为“现场纪律”：看得见（地图）、控得住（切片）、验得实（证据）。代码只展示核心门禁与红线。 |
| **缺少作者真情实感** | 通篇全知全能的教导口吻，缺乏自嘲与现场互动。 | 穿插真实口语：“好不痛快”、“名校实习生砸墙”、“工厂倒班白班夜班交接”。 |
| **收束功利叫卖** | 原文末尾直接挂上“写在最后的干货：一套工作流 [链接]”，破坏了整篇随笔的心法意境。 | 自然收束到“模型是跑马场里的烈马，Harness 是缰绳与轨道”，重塑工程师掌控复杂度的尊严。 |
